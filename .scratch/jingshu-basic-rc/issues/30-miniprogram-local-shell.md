# 30 — 小程序本地沙箱与预约优先外壳

**What to build:** 让体验者打开原生微信小程序后，在无需登录或网络 API 的情况下获得可持久化的本地三店演示世界和预约优先首页。

**Blocked by:** 01 — 可复现工作区与门禁骨架；02 — 统一跨端设计基线与合成命名；03 — 公开入口与版本化三店沙箱；05 — 双时钟、时间推进与轮换重置。

**Status:** ready-for-agent

- [ ] 交付物是原生微信小程序，不把 Vite 手机原型或浏览器设备框架作为生产运行时。
- [ ] 小程序使用纯 TypeScript 共享领域规则和本地存储适配器，不请求竞枢 Web API，也不与 Web 沙箱同步。
- [ ] 首次启动创建带 schema 版本和种子版本的本地沙箱；再次启动恢复已提交状态，旧版本执行显式本地迁移。
- [ ] 迁移失败时不进入部分可写状态，提供重试和二次确认的“重建本地演示”。
- [ ] MP-00 覆盖首次创建、恢复、迁移、失败与重建；MP-01 以“预约座位/查找可订座位”为唯一主要任务。
- [ ] MP-03/04 展示棱镜旗舰店、星桥标准店、极点新店及栖光市、营业时间、座位规模、机型和价格概览。
- [ ] 四个一级导航固定为首页、门店、行程、会员；重复点击当前 Tab 不重复入栈或触发转场。
- [ ] MP-18 展示本地存储、schema/种子版本、不与 Web 同步及重置入口；重置只影响当前设备并恢复当前版本标准种子。
- [ ] MP-19 覆盖安全错误、存储不可用、迁移失败和恢复动作，不显示堆栈或内部技术名。
- [ ] 所有主页面持续显示“本地演示”，明确不扣款、不要求真实身份且不与 Web 同步。
- [ ] 使用 Product Design 插件的 image-to-code 工作流，以已选小程序视觉源和可运行原型的 MP-00/01/03/04/18/19 状态实现原生页面；导航、初始化、设置和重置均有真实交互。
- [ ] 使用 Product Design design-qa 对微信开发者工具的原生截图与设计原型执行同状态比较，至少覆盖 393×852 iPhone 和 427×952 Android 视口；P0/P1/P2 清零并通过。
- [ ] 本地适配器契约测试覆盖首次创建、重启恢复、迁移、失败回滚、主动重置和清缓存重建。
