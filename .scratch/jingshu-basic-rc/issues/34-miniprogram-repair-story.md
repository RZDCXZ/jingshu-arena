# 34 — 小程序报修与角色外本地故事推进

**What to build:** 让使用中顾客在小程序本机提交耳机故障，并通过明确的演示工具看到公开维修、预约退款和座位恢复结果。

**Blocked by:** 14 — 顾客与店员创建座位报修及私有图片；16 — 备件领退、解决说明与维修验证闭环；31 — 小程序预约完整流程；33 — 小程序商品订单流程。

**Status:** ready-for-agent

- [ ] 只有使用中预约展示座位报修入口，报修自动关联当前座位和机型。
- [ ] MP-13 提供最多 500 字描述、请勿填写真实个人信息提示，以及最多三张本地 JPEG/PNG/WebP 图片。
- [ ] MP-14 覆盖相册/相机权限拒绝、类型/大小错误、预览、删除、满三张、内置样例图和无图继续。
- [ ] 图片只保存在当前设备本地沙箱，不出现“上传云端”或“与 Web 同步”措辞。
- [ ] 同一座位已有未关闭报修时打开既有报修详情，不创建重复记录。
- [ ] MP-15 展示新建、已分派、处理中、待验证、已关闭的公开动态、座位/预约影响、验证结果和模拟退款，不显示内部笔记或库存成本。
- [ ] 角色外“推进本地演示”明确只推进本机合成故事，并以合法状态顺序生成分派、维修、替换耳机、解决说明、验证和座位恢复结果。
- [ ] 维修开始对本地预约执行与 Web 相同的设备中断价格片段退款；已支付商品订单继续柜台履约。
- [ ] 本地状态、图片引用、预约、退款、报修事件、订单和引导进度原子持久化，重启后保持一致。
- [ ] 使用 Product Design 插件的 image-to-code 工作流实现 MP-13/14/15 的描述键盘、图片回退、样例图、提交、公开时间线和故事推进交互。
- [ ] 使用 Product Design design-qa 在 iPhone 与 Android 的键盘打开、权限拒绝、样例图、处理中、退款和关闭状态下比较原型，复核真实图片资产与安全区，P0/P1/P2 清零并通过。
- [ ] 测试覆盖重复报修、图片拒绝/失败、合法推进顺序、设备退款、订单继续履约、关闭后新故障和重启恢复。
