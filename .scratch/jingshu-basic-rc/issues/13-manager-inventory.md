# 13 — 店长库存、盘点、入库、补偿与告警

**What to build:** 让店长在不覆盖历史的前提下掌握本店商品与备件库存，并通过入库、盘点和补偿流水纠正经营事实。

**Blocked by:** 11 — 顾客商品下单、整单库存预留与模拟支付；12 — 店员商品订单履约、取消与损耗。

**Status:** ready-for-agent

- [ ] WEB-S08 和 WEB-M06 同时显示库存类别、账面库存、预留库存、可用库存、独立阈值、告警状态及最近关联流水。
- [ ] 店员只能查看余额并从订单或报修进入授权库存动作，不能直接编辑库存数量。
- [ ] 店长可执行手工入库，输入正整数、业务原因并产生正向库存流水。
- [ ] 盘点要求输入实际数量，提交前预览与账面数量的差额，确认后以差额流水调整而不是覆盖历史。
- [ ] 错误流水通过新的补偿流水修正，必须关联或说明原操作；历史库存流水不可编辑或删除。
- [ ] 可用库存小于或等于项目阈值时自动出现低库存告警，补货超过阈值后自动解除。
- [ ] 商品和八类维修备件共用统一门店库存账本，但顾客商品目录继续排除备件。
- [ ] 所有数量为整数且不为负，入库、盘点、补偿、告警、审计在事务中保持一致；跨店与总部直接改量请求被拒绝。
- [ ] 使用 Product Design 插件的 image-to-code 工作流实现库存列表、筛选、盘点、入库、差额预览、最近流水展开/收起和告警交互；业务弹窗必须使用专用字段而非通用命令表单。
- [ ] 使用 Product Design design-qa 在 1440×1024 和 1024×768 下对照管理端原型，复核三联库存、流水对齐、告警间距、560×542 盘点弹窗及无溢出状态，P0/P1/P2 清零并通过。
- [ ] 契约测试覆盖账面/预留/可用恒等式、阈值边界、补偿不修改原流水和所有失败回滚。
