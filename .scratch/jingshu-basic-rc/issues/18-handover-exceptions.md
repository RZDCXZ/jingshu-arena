# 18 — 交接班快照、接班确认与异常

**What to build:** 让交班员工冻结当时未完成业务证据并提交给下一班，同时保留迟交和长期未确认等经营异常。

**Blocked by:** 12 — 店员商品订单履约、取消与损耗; 13 — 店长库存、盘点、入库、补偿与告警; 16 — 备件领退、解决说明与维修验证闭环; 17 — 店员班次、模拟考勤与手动签退。

**Triage:** ready-for-agent

**State:** resolved

- [x] 交班提交时保存未完成预约、商品订单、报修和低库存告警摘要，以及最多 500 字补充说明。
- [x] 交接快照保存提交时事实，提交后不可编辑且不随后续业务状态变化。
- [x] 交班人提交后即可手动签退，不必等待接班人确认。
- [x] 接班员工可以随后确认承接，确认人、业务时间和服务器记录时间均可追溯。
- [x] 班次结束 30 分钟仍未提交、迟交或长期未确认分别形成可解释交接异常，不混同考勤异常。
- [x] 交接内容不包含现金盘点、真实支付对账或自由扩展的敏感字段。
- [x] WEB-S10 展示交接事项、冻结快照、说明输入、提交状态和接班确认；WEB-M09 提供异常与只读快照视图。
- [x] 只有同店合格员工能提交或确认，店长只能在所属门店查看，总部不执行交接；越权请求被拒绝并审计。
- [x] 使用 Product Design 插件的 image-to-code 工作流实现交接文本输入、快照预览、提交、不可编辑状态、确认和异常下钻，按钮与提示具有真实行为。
- [x] 使用 Product Design design-qa 在 1440×1024 和 1024×768 下对照管理端原型，复核交接提示、文本域、按钮间距、只读快照与焦点，P0/P1/P2 清零并通过。
- [x] 测试覆盖快照冻结、提交后业务继续变化、提交即签退、确认、迟交、未确认及跨店拒绝。
