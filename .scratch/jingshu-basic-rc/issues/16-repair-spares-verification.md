# 16 — 备件领退、解决说明与维修验证闭环

**What to build:** 让处理人领用替换耳机、提交解决结果，再由另一位同店员工或店长验证并安全恢复座位。

**Blocked by:** 13 — 店长库存、盘点、入库、补偿与告警; 15 — 报修处理联动座位维护、预约中断与模拟退款。

**Triage:** ready-for-agent

**State:** resolved

- [x] 只有处理中的报修可以领用备件，领用数量不得超过可用库存；库存扣减、使用记录、流水、报修事件和审计原子提交。
- [x] 关闭前可退回尚未消耗的备件，累计退回不得超过该报修领用量，并产生关联退回流水。
- [x] 主演示可以从棱镜旗舰店领用一副无品牌替换耳机，顾客侧只看到公开说明而不看到成本或内部库存细节。
- [x] 从处理中进入待验证前必须提交最多 500 字的解决说明；待验证期间座位继续维护。
- [x] 同店店员或店长可记录验证失败及原因，报修返回处理中且座位保持维护。
- [x] 验证成功时关闭报修与恢复座位正常在同一事务完成；已关闭报修不可重开，后续故障必须新建。
- [x] 处理人、验证人、业务发生时间、服务器记录时间、备件与事件链均可追溯，跨店或无能力请求被拒绝并审计。
- [x] WEB-S07 和 WEB-M02 提供领用、退回、提交解决说明、验证成功/失败的专用交互，当前状态只显示合法主动作。
- [x] 使用 Product Design 插件的 image-to-code 工作流实现备件、解决说明、待验证、失败退回与成功关闭状态，并保持管理端与顾客公开时间线一致。
- [x] 使用 Product Design design-qa 在 1440×1024 店员/店长详情和 360px 顾客关闭状态下对照原型，复核状态、库存证据、座位恢复和按钮焦点，P0/P1/P2 清零并通过。
- [x] 事务与状态机测试覆盖备件不足、流水失败、事件失败、超额退回、验证失败、验证成功和重复关闭。
