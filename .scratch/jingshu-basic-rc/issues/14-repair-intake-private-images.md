# 14 — 顾客与店员创建座位报修及私有图片

**What to build:** 让顾客或本店店员为明确座位创建报修，并能在不泄露元数据或跨沙箱文件的情况下附加可选故障图片。

**Blocked by:** 04 — 服务端角色上下文与共享演示壳；09 — 店员办理到店、使用与完成预约。

**Status:** ready-for-agent

- [ ] 顾客只能为自己当前有效预约的座位报修；店员只能选择本店座位，机型由座位自动带出，不提供非座位设施入口。
- [ ] 报修创建为新建状态且不立即改变座位运营状态；同一座位最多一张未关闭报修，重复提交返回并打开已有报修。
- [ ] 故障描述为规范化纯文本、最多 500 字，并提示不要填写真实个人信息。
- [ ] 每张报修最多关联三张 JPEG、PNG 或 WebP 图片，每张不超过 5 MB，宽高不超过 4096，总像素不超过一千六百万。
- [ ] Web 上传意图绑定当前沙箱、报修、类型和大小并短期一次性有效；完成时核验扩展名、声明类型、magic bytes、实际解码、尺寸和像素数。
- [ ] 原图先进入私有隔离区，服务端重新编码移除 EXIF 等元数据后才进入私有成品区，随机对象名且只通过短期签名读取。
- [ ] 直传和单图代理适配器执行相同净化规则；不支持 Base64 或多图批量代理，无法安全净化时只允许内置样例图且不保留原文件。
- [ ] 图片权限拒绝、上传失败或净化失败不阻塞文字报修；未经净化的文件不得显示为已保存。
- [ ] 顾客仅能查看自己的成品图，同店员工和获授权总部按对象范围查看；跨顾客、门店、沙箱签名读取均被拒绝。
- [ ] 使用 Product Design 插件的 image-to-code 工作流实现 Web H5 的 MP-13/14/15 报修入口和管理端 WEB-S06 创建入口；描述输入、图片预览/删除、权限拒绝、样例图、重复报修和提交结果均可操作。
- [ ] 使用 Product Design design-qa 分别在 360px 顾客 H5 和 1440×1024 店员报修弹窗状态下对照两套原型，复核键盘安全区、隐私文案、真实图片资产、下拉选择和错误恢复，P0/P1/P2 清零并通过。
- [ ] 安全集成测试覆盖伪造类型、主动内容、超尺寸、元数据移除、上传意图重放、跨沙箱读取和失败清理。
