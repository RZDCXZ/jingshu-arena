# 33 — 小程序商品订单流程

**What to build:** 让小程序体验者从已到店或使用中的本地预约购买柜台商品，并看到整单库存、模拟支付与履约状态完整变化。

**Blocked by:** 11 — 顾客商品下单、整单库存预留与模拟支付；12 — 店员商品订单履约、取消与损耗；31 — 小程序预约完整流程。

**Status:** ready-for-agent

- [ ] 只有本地预约已到店或使用中时显示商品主入口；其他状态解释资格而不提供可执行下单按钮。
- [ ] MP-10 展示本店上架商品、门店价、库存提示、数量步进、购物车和动态合计，不显示维修备件。
- [ ] 整单库存不足时指出不足商品、保留购物车并不创建任何订单或部分预留。
- [ ] MP-11 展示关联预约/座位、商品快照、商品体验券、动态总额和不扣款模拟支付。
- [ ] MP-12 展示待模拟支付、已模拟支付、制作中、待取、已完成、已取消和已过期，并区分成功进度线和分支终态。
- [ ] 本地适配器执行与 Web 相同的十分钟预留、整单原子性、券状态、制作前释放、制作后损耗、销售扣减和预约终止规则。
- [ ] 角色外本地演示工具只触发预置合法的制作中、待取和完成结果，不让顾客看到员工操作权限。
- [ ] 订单金额、固定提交栏、详情和行程摘要均由同一商品快照计算，不允许出现显示金额漂移。
- [ ] 每个状态变化立即持久化，重启后库存、订单、券和成长值保持一致。
- [ ] 使用 Product Design 插件的 image-to-code 工作流，以 MP-10/11/12 对应状态实现原生商品卡、购物车、确认、支付、进度和取消交互。
- [ ] 使用 Product Design design-qa 在 iPhone 与 Android 视口比较空购物车、低库存、三件商品动态金额、支付、制作中、待取和完成状态，P0/P1/P2 清零并通过。
- [ ] 本地适配器测试穷举订单状态、整单失败、券、库存恒等式、损耗、成长值和重启恢复。
