# 28 — 沙箱容量、自然过期与可重试清理

**What to build:** 让公共演示在容量耗尽和沙箱到期时保持可解释、不可误写，并最终安全清除业务记录与私有图片。

**Blocked by:** 05 — 双时钟、时间推进与轮换重置; 14 — 顾客与店员创建座位报修及私有图片; 27 — 实时失效通知、轮询与只读降级。

**Triage:** ready-for-agent

**State:** resolved

- [x] 活跃沙箱采用可配置容量上限，初始为 200；已有沙箱继续可用，达到上限的新访客进入只读标准快照并看到稍后重试说明。
- [x] 创建和重置默认受签名访客每小时五次、每天二十次及较宽松 IP 上限约束，阈值可配置且限流失败不产生部分沙箱。
- [x] Web 沙箱从创建起 24 小时后按真实服务器时间立即停止全部读取和写入，业务时间推进不能延长或缩短寿命。
- [x] 过期或重置先标记不可访问，再分批删除私有隔离区和成品区 Blob，之后按依赖顺序分批删除业务行。
- [x] 清理失败进入可重试状态且绝不恢复访问；完成后只保留不含业务内容、自由文本、人物或文件标识的最小删除回执。
- [x] 未关联报修的孤儿上传一小时后清理，文件删除与数据库引用失败均能安全重试。
- [x] WEB-G01/G06/G07 展示容量已满、自然到期、旧沙箱失效、清理中无须等待和创建新沙箱的恢复路径。
- [x] 使用 Product Design 插件的 image-to-code 工作流实现容量只读、沙箱过期、重置后旧标签和新建恢复状态，不提供会误导用户继续保存的控件。
- [x] 使用 Product Design design-qa 在 1440×1024 和 360px 下对照管理端原型的只读、过期和重置状态，验证信息层级、禁用语义和恢复主动作，P0/P1/P2 清零并通过。
- [x] 固定真实时钟测试覆盖 TTL、容量竞争、限流、Blob 优先清理、批次重试、孤儿文件和最小删除回执。
