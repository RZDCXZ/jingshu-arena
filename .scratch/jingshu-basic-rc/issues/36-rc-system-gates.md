# 36 — 全系统安全、并发、可访问性与性能门禁

**What to build:** 让完整竞枢候选版本通过可重复的自动化和生产式验证，证明权限、事务、页面、性能和多端规则在集成后仍然成立。

**Blocked by:** 29 — 基于业务证据的十二步 Web 主演示; 35 — 小程序全故事、异常恢复与开发者工具门禁。

**Triage:** ready-for-agent

**State:** open

- [ ] 五个测试接缝全部运行：纯领域规则、存储适配器契约、Hono 与真实 Postgres、Web 浏览器主演示、小程序本地运行时。
- [ ] 预约、商品订单和报修的合法/非法状态转换、权限矩阵、库存事务和全部 P0 风险被穷举，不以单一覆盖率数字替代。
- [ ] 空库迁移、RLS、时间范围排斥约束、索引、seed/reset、事务和并发测试全部使用真实临时 Postgres。
- [ ] 二十并发预约、库存为五的二十请求、同幂等键二十重试均得到规格规定的唯一/有限成功结果且无重复副作用。
- [ ] 顾客、店员、店长、总部的允许/拒绝矩阵覆盖跨门店、跨沙箱、对象枚举、旧角色上下文和缺少 RLS 上下文。
- [ ] CSRF、Origin、SameSite、安全 Cookie、会话轮换、限流、稳定错误码、文本规范化、日志白名单和 Secret 扫描通过。
- [ ] 图片意图、magic bytes、解码、尺寸、像素、重新编码、元数据移除、签名读取、跨沙箱拒绝和两种运输适配器通过安全测试。
- [ ] Playwright 覆盖完整 Web 主故事及空、错、慢、拒绝、超时、重复、只读、SSE 重连、轮询和手动刷新；Chromium 与 WebKit 门禁通过。
- [ ] 可访问性覆盖语义结构、完整键盘路径、可见焦点、字段错误关联、对比度、非颜色唯一编码、44px 小程序触控目标和图表文本替代。
- [ ] 顾客 H5 连续五次中位数满足 LCP ≤2.5 秒、CLS ≤0.1、交互反馈 ≤200 毫秒，初始 JavaScript gzip ≤300 KB。
- [ ] 热实例二十并发虚拟用户满足读取 p95 ≤500 毫秒、写入 p95 ≤1 秒、错误率 <1%；冷启动独立报告。
- [ ] 完整沙箱热物化 ≤3 秒，旗舰店座位图首次可交互 ≤1 秒且无超过 200 毫秒主线程长任务。
- [ ] Web、API、小程序构建、格式、lint、TypeScript strict、依赖漏洞、迁移和全部测试形成必需 CI 合并门禁，自动化绝不连接生产数据库。
- [ ] 使用 Product Design 插件对生产 Web 与原生小程序执行最终跨页面 design-qa，源设计和实现截图同输入、同视口、同数据、同状态比较；所有 P0/P1/P2 清零且结果为 passed。
- [ ] 管理端、顾客 H5、小程序的设计覆盖或 QA 在契约、视觉状态或交互发生变化时已同步更新，没有以既有原型 passed 记录替代生产验收。
