# 05 — 双时钟、时间推进与轮换重置

**What to build:** 让访客无需真实等待即可安全推进演示业务时间，并能通过创建全新标准沙箱重置整个四角色故事。

**Blocked by:** 03 — 公开入口与版本化三店沙箱; 04 — 服务端角色上下文与共享演示壳。

**Triage:** ready-for-agent

**State:** resolved

- [x] 每个沙箱拥有共享的上海业务时钟，初始锚定真实时间并正常流逝；真实服务器时间独立控制会话、安全、限流、幂等和清理期限。
- [x] WEB-G04 只提供“推进到下一事件”和“+30 分钟”，显示推进前后时间、影响说明和 24 小时累计上限，不允许回拨或任意输入。
- [x] 推进命令使用幂等键，在一个事务中更新时间并执行已注册的到期处理；任一步失败则时钟和业务状态全部回滚。
- [x] 到期处理采用固定顺序扩展点，后续预约、订单、考勤和交接 ticket 可在不改变外部契约的情况下接入。
- [x] 审计事件同时保存业务发生时间和不可变服务器记录时间；业务快进不能改变沙箱 TTL、限流或文件清理时间。
- [x] WEB-G06 在重置前明确列出四角色数据影响；确认后创建新的最新种子沙箱、轮换会话、立即封锁旧沙箱并让旧标签收到失效结果。
- [x] 重置成功回到主演示起点且旧对象不可继续操作；失败时保留当前沙箱并提供安全重试。
- [x] 使用 Product Design 插件的 image-to-code 工作流实现时间推进、影响确认、处理中、成功、事务失败、达上限以及重置二次确认等状态。
- [x] 使用 Product Design design-qa 在与管理端原型相同的角色、时间和弹窗状态下比较生产实现，P0/P1/P2 清零并通过。
- [x] 固定双时钟测试覆盖前进、上限、重复提交、事务回滚、重置轮换和真实安全期限不受推进影响。
