# 35 — 小程序全故事、异常恢复与开发者工具门禁

**What to build:** 让原生小程序作为独立作品完整、稳定地运行四条顾客故事，并用开发者工具和真机证据证明不是一次性页面 Mock。

**Blocked by:** 30 — 小程序本地沙箱与预约优先外壳; 31 — 小程序预约完整流程; 32 — 小程序会员与行程历史; 33 — 小程序商品订单流程; 34 — 小程序报修与角色外本地故事推进。

**Triage:** ready-for-agent

**State:** open

- [ ] MP-00 至 MP-19 全部可从正常导航或审阅入口到达，正式顾客导航仍只包含首页、门店、行程和会员。
- [ ] 从首次启动完整走通预约、商品订单、报修和本地重置四条故事，业务资格、状态和下一动作始终清晰。
- [ ] 关闭并重新打开后恢复当前故事；schema 升级执行迁移；迁移失败、存储写失败和清缓存均有诚实恢复路径。
- [ ] 重复点击、处理中、冲突、库存不足、图片权限拒绝、非法状态和未知错误不产生重复或部分业务结果。
- [ ] 原生实现不请求竞枢 Web API，不出现员工/店长/总部后台，不声称与 Web 状态同步。
- [ ] 所有文字输入、图片和权限符合最小权限；不请求位置、联系人、麦克风或电话。
- [ ] 关键触控目标至少 44px，状态不只靠颜色表达，控件具备可理解的无障碍标签，字体放大不裁切核心金额、状态或错误。
- [ ] 在微信开发者工具中通过 TypeScript、构建、组件/交互测试，并在至少一台真机走完本地主演示；缺少账号或真机授权时明确记录为后续发布前提。
- [ ] 小程序主包和分包结构可测量，非首屏页面合理分包；正式 80% 上限在基础设施探针确认后复核。
- [ ] 使用 Product Design 插件对全部关键生产页面执行最终 design-qa：将原型源状态和微信开发者工具/真机截图放入同一比较输入，覆盖 393×852 与 427×952 视口。
- [ ] 所有 Product Design QA 的 P0/P1/P2 均修复，最终结果为 passed；若生产约束要求改变原型交互或视觉状态，同步更新设计覆盖和最新 QA。
- [ ] 设计原型自身的受保护移动运行时检查、构建和既有测试继续通过，生产实现不得通过修改原型基础设施掩盖差异。
