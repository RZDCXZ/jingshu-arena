# 11 — 顾客商品下单、整单库存预留与模拟支付

**What to build:** 让已到店或使用中的顾客为当前门店预约创建柜台取货订单，并看到整单库存、体验券和不扣款模拟支付的真实事务结果。

**Blocked by:** 09 — 店员办理到店、使用与完成预约；10 — 会员成长、体验券与统一行程。

**Status:** ready-for-agent

- [ ] 只有在目标门店拥有已到店或使用中预约的顾客才能下单，订单必须关联该预约、门店和座位。
- [ ] 顾客目录只展示总部商品中本店已上架的可销售商品和门店售价，维修备件、下架商品及其他门店配置不可见。
- [ ] 创建待模拟支付订单时整单原子检查并预留整数库存；任一行不足则订单、券占用、预留、流水和事件全部不创建。
- [ ] 可用库存始终等于账面库存减预留库存，任何状态下不得为负，预留不得超过账面库存。
- [ ] 待模拟支付保留十分钟并排他占用至多一张商品体验券；超时或支付前取消释放整单预留和体验券。
- [ ] 创建时保存商品名称、单价、数量、优惠和总额快照；后续改名、改价、下架不修改历史订单。
- [ ] 模拟支付入口、确认和结果持续标明“不扣款”，成功后订单进入已模拟支付。
- [ ] 关联预约在订单模拟支付前进入终态时订单立即取消；模拟支付后预约终止不自动取消订单，订单继续柜台取货。
- [ ] 创建和模拟支付命令均支持幂等重试，相同键不会重复预留库存、占用券或生成订单。
- [ ] 使用 Product Design 插件的 image-to-code 工作流实现 MP-10/MP-11 及订单详情初始状态对应的 Web H5；商品数量步进、购物车、券选择、动态合计、整单不足、倒计时和模拟支付均可操作。
- [ ] 使用 Product Design design-qa 在 360px 的空购物车、低库存、整单不足、待支付和支付成功状态下比较设计原型，确认内容区与固定提交栏金额一致，P0/P1/P2 清零并通过。
- [ ] 真实 Postgres 并发测试证明库存为五时二十个不同请求最多成功五份，同一幂等请求并发二十次只产生一个订单及一组副作用。
