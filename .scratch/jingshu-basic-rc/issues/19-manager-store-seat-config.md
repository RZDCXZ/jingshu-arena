# 19 — 店长门店资料、区域与座位配置

**What to build:** 让店长安全维护所属固定门店的展示资料、营业规则、区域和座位，同时保留所有被业务引用的历史。

**Blocked by:** 04 — 服务端角色上下文与共享演示壳; 06 — 顾客三店浏览、座位可订性与价格预览。

**Triage:** ready-for-agent

**State:** resolved

- [x] WEB-M03 允许店长维护所属门店工作名称、虚构城市、介绍、营业时间和展示信息，且始终提示为虚构演示门店。
- [x] WEB-M04 支持区域和座位的新建、编辑，以及为座位选择总部机型档案；座位编号在门店内唯一。
- [x] 基础 RC 固定三店，店长不能新增、删除、停用门店或修改其他门店。
- [x] 停用座位前必须展示并处理有效预约和未关闭报修依赖；已经被业务引用的区域、座位和机型引用只能归档/停用。
- [x] 未被引用的草稿允许删除，所有配置变化保留审计并不改写历史预约或报修快照。
- [x] 营业时间变化只影响未来业务，不能让已存在的合法预约历史失效。
- [x] 顾客门店详情和座位查询在服务端确认保存后读取新配置，不显示未经确认的乐观成功。
- [x] 使用 Product Design 插件的 image-to-code 工作流实现门店资料、营业规则、区域、座位和机型的专用表单、依赖确认及成功反馈，不回退到通用业务命令。
- [x] 使用 Product Design design-qa 在 1440×1024 和 1024×768 下对照管理端原型，检查表格间距、弹窗字段、保存未来配置、长名称和依赖提示，P0/P1/P2 清零并通过。
- [x] 权限和数据库测试覆盖座位唯一编号、跨店拒绝、历史引用归档、依赖阻断和并发保存。
