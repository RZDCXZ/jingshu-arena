# 29 — 基于业务证据的十二步 Web 主演示

**What to build:** 让一位无需陪同的访客从公开入口顺序切换四个角色，完整走完预约、订单、维修、库存、看板、导出和重置故事。

**Blocked by:** 09 — 店员办理到店、使用与完成预约; 12 — 店员商品订单履约、取消与损耗; 16 — 备件领退、解决说明与维修验证闭环; 22 — 单店经营看板与经营日下钻; 23 — 本店审计与筛选 CSV 导出; 26 — 总部三店比较、全沙箱审计与导出; 27 — 实时失效通知、轮询与只读降级; 28 — 沙箱容量、自然过期与可重试清理。

**Triage:** ready-for-agent

**State:** open

- [ ] WEB-G03 提供可收起并重新打开的十二步清单，每步显示目标角色、业务对象、入口、完成条件、已有证据和下一动作。
- [ ] 清单进度只从主演示顾客、业务对象、业务事件、库存流水、导出和重置事件推导，不能手工勾选或被背景历史提前完成。
- [ ] 完整主路径从公开入口创建沙箱，在棱镜旗舰店完成竞技型两小时立即预约、预约体验券和模拟支付。
- [ ] 店员办理到店和使用；顾客创建并支付商品订单；店员可完成或保留支付后履约中的订单。
- [ ] 业务时间推进 30 分钟后，顾客提交“耳机右声道无声”，店员分派、开始处理、领用一副替换耳机并提交解决说明。
- [ ] 维修开始后预约按价格片段产生模拟退款，座位维护；店长验证成功关闭报修并恢复座位。
- [ ] 店长看到单店指标和审计变化；总部看到三店比较并成功导出当前筛选 CSV；最后重置回起点。
- [ ] 每个完整沙箱物化独立三店配置、最近十四个经营日历史、当前积压和主演示数据；指标、列表和导出均来自记录而非预计算常量。
- [ ] 种子生成保持确定性、单事务和幂等；应用至少兼容仍可访问的旧种子 24 小时，新版本只影响新建或重置沙箱。
- [ ] 任一步失败保留此前已提交合法状态并给出恢复入口；角色切换或刷新后清单恢复同一进度，重置后归零。
- [ ] 使用 Product Design 插件的 image-to-code 工作流实现主演示抽屉的展开、收起、受阻、完成和下一动作，并保持与管理端原型的共享壳和视觉层级一致。
- [ ] 使用 Product Design design-qa 对十二步关键帧执行同视口、同状态比较，覆盖 1440×1024 管理端、1024×768 管理适配和 360px 顾客 H5；P0/P1/P2 清零并通过。
- [ ] Playwright 从全新浏览器会话完成整条故事，验证同一沙箱、事件推导进度、旧标签失效、导出内容和重置后的旧对象拒绝。
