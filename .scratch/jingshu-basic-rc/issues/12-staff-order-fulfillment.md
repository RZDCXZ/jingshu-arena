# 12 — 店员商品订单履约、取消与损耗

**What to build:** 让店员从本店订单队列依次完成制作、待取和交付，并让不同取消时点产生正确的库存、体验券和模拟退款结果。

**Blocked by:** 04 — 服务端角色上下文与共享演示壳; 11 — 顾客商品下单、整单库存预留与模拟支付。

**Triage:** ready-for-agent

**State:** open

- [ ] WEB-S04 按已模拟支付、制作中、待取和异常状态筛选本店订单，并展示关联预约、座位、等待时间和模拟金额。
- [ ] WEB-S05 展示商品快照、整单库存预留、体验券、关联预约和不可变事件，状态动作必须逐级执行。
- [ ] 已模拟支付只能进入制作中，制作中只能进入待取，待取只能进入已完成；任何跨级或重复非法动作被拒绝并审计。
- [ ] 完成订单时整单预留按销售扣减，产生不可变库存流水、模拟营业额和按最终模拟金额计算的成长值。
- [ ] 顾客仅可在制作开始前取消；店员可在完成前带原因取消。
- [ ] 制作前取消释放库存、全额模拟退款并恢复体验券；制作开始后取消按订单损耗扣减、全额模拟退款但不恢复体验券。
- [ ] 预约因设备故障结束后，已模拟支付订单仍保留在正常柜台履约队列；不支持部分领取、部分取消或缺货行自动删除。
- [ ] 订单状态、库存余额、库存流水、业务事件、成长值、模拟退款和审计在同一事务成功或回滚。
- [ ] 使用 Product Design 插件的 image-to-code 工作流实现 WEB-S04/S05；筛选、打开详情、开始制作、标记待取、完成和带原因取消均有处理中、成功和失败反馈。
- [ ] 使用 Product Design design-qa 在 1440×1024 和 1024×768 的队列、详情和取消弹窗状态下对照管理端原型，检查信息密度、状态进度、主动作和键盘焦点，P0/P1/P2 清零并通过。
- [ ] 状态机及事务测试穷举七种状态、制作前/后取消、预约终止和重复命令。
