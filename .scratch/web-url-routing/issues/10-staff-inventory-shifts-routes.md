# 10 — 店员库存、班次与交接路由

**What to build:** 为店员库存、考勤和交接工作建立可恢复 URL，让筛选、表单保护和角色壳导航不再依赖内存页签。

**Blocked by:** 03 — 服务端角色上下文与深链守卫.

**Triage:** ready-for-agent

**State:** open

- [ ] 店员库存侧栏链接进入 `/staff/inventory`，浏览器标题、页面标题和当前侧栏状态同步。
- [ ] 库存的 `q`、`kind` 和 `alert` 筛选使用查询参数；允许值规范化、未知值移除，并能通过后退、前进和刷新恢复。
- [ ] 班次父路径 `/staff/shifts` 规范重定向到 `/staff/shifts/attendance`，不保留第二套可继续使用的业务地址。
- [ ] 考勤与交接分别使用 `/staff/shifts/attendance` 和 `/staff/shifts/handover`，二者之间及返回工作台均使用真实链接。
- [ ] 库存调整、签到签退和交接提交继续走现有服务端动作与角色授权，成功后停留在对应规范 URL 并刷新数据。
- [ ] 交接草稿或其他脏表单在站内路由切换、浏览器后退和页面卸载前触发现有确认保护；取消离开时 URL 与表单保持原状。
- [ ] 直接打开、刷新或浏览器后退不会显示前一个库存筛选、班次或交接记录的陈旧内容。
- [ ] `1440 × 1024` 和 `1024 × 768` E2E 覆盖库存筛选、考勤、交接、脏表单保护、焦点和横向溢出。
