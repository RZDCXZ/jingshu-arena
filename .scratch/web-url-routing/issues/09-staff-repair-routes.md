# 09 — 店员报修队列与详情路由

**What to build:** 让店员报修队列和报修详情拥有稳定 URL，使选择、刷新、维修动作和对象授权在共享角色壳内保持一致。

**Blocked by:** 03 — 服务端角色上下文与深链守卫.

**Triage:** ready-for-agent

**State:** open

- [ ] 店员报修侧栏链接进入 `/staff/repairs`，当前侧栏、浏览器标题和页面标题同步。
- [ ] 选择报修进入 `/staff/repairs/:repairId`，直接打开或刷新会读取当前状态、座位影响、备件、事件和合法动作。
- [ ] 新建报修成功进入新对象的唯一详情地址；重复座位报修打开既有对象详情而不创建第二个 URL 身份。
- [ ] 分派、开始处理、备件领退、解决说明和验证结果继续使用现有按钮与服务端授权，状态变化不改变详情 URL。
- [ ] 从队列进入详情后浏览器后退恢复队列位置；直接详情提供返回默认报修队列的真实链接。
- [ ] 报修 ID 不扩大门店和角色能力，跨店、不存在和无权对象显示相同安全边界。
- [ ] 详情加载和错误状态留在目标 URL，且新 URL 下不闪现上一报修内容。
- [ ] `1440 × 1024` 和 `1024 × 768` E2E 覆盖队列、详情、刷新、维修动作、历史、焦点和横向溢出。
