## 1. 文档定位

本文档把[基础 RC 规格](../../.scratch/jingshu-basic-rc/spec.md)转译为可直接用于信息架构、线框图、高保真界面和交互原型的顾客侧设计输入。它定义产品目标、页面范围、主流程、状态、内容优先级和设计验收标准，不提前锁定颜色、字体、插画或具体视觉风格。

设计与实现发生冲突时，按以下顺序处理：

1. [领域词汇](../../CONTEXT.md)决定业务名词及其含义。
2. `spec.md` 和已接受 ADR 决定业务规则、权限与边界。
3. 本文档决定小程序的信息架构、页面职责和信息呈现。
4. 视觉稿决定品牌表达与组件外观，不得改变前三项。

必须按条件查阅的 ADR：

- 设计座位图和预约筛选时，查阅 [ADR-0003](../../docs/adr/0003-derive-seat-availability-by-time-range.md)。
- 设计价格明细和历史金额时，查阅 [ADR-0004](../../docs/adr/0004-snapshot-reservation-price-on-creation.md) 与 [ADR-0013](../../docs/adr/0013-version-future-price-plans.md)。
- 设计体验券选择、取消结果时，查阅 [ADR-0007](../../docs/adr/0007-reserve-coupon-with-pending-transaction.md)。
- 设计本地数据说明、重置或跨端提示时，查阅 [ADR-0015](../../docs/adr/0015-share-domain-rules-not-runtime-state.md)。
- 设计经营日期与跨午夜时间时，查阅 [ADR-0002](../../docs/adr/0002-business-day-starts-at-0600.md)。

## 2. 设计目标

小程序要让第一次接触竞枢的体验者在不注册、不提交真实身份、不发生真实支付的前提下，独立理解并体验以下顾客闭环：

1. 了解三家虚构门店与本地演示边界。
2. 选择日期、时段、区域、机型和明确座位。
3. 查看半小时价格片段、使用体验券并完成不扣款的模拟支付。
4. 查看预约进度，在已到店或使用中状态下购买柜台取货商品。
5. 为当前座位提交报修，并查看公开处理动态与模拟退款结果。
6. 查看会员等级、成长值、体验券和统一历史。
7. 关闭并重开小程序后继续当前本地故事，或主动重置到标准种子。

成功标准不是“页面齐全”，而是体验者能始终回答三个问题：我正在体验什么、当前业务处于什么状态、下一步可以做什么。

## 3. 产品边界

### 3.1 必须持续可见的事实

- 这是演示产品，门店、人物、订单、金额和经营数据全部为合成数据。
- 小程序数据只保存在当前设备的本地沙箱中，不请求竞枢 Web API，也不与 Web 沙箱同步。
- 模拟支付不会扣款；入口、确认动作和结果页都必须重复说明，而非只在首次启动提示一次。
- 小程序不要求真实姓名、电话、邮箱、地址、证件或账号登录。
- 自由文本入口提示“请勿填写真实个人信息”。

### 3.2 小程序内包含

- 门店浏览、门店详情与营业时间。
- 日期、时段、区域、机型筛选与座位图。
- 立即预约、普通预约、价格快照、体验券、模拟支付与取消。
- 会员档案、青铜/白银/黄金等级、成长值与体验券。
- 商品目录、购物车、整单库存校验、订单模拟支付与进度。
- 当前座位报修、本地图片或样例图、公开处理动态与模拟退款。
- 预约、订单、报修和模拟退款统一历史。
- 本地 schema 迁移、持久化、演示引导和主动重置。

### 3.3 小程序内不包含

- 店员、店长或总部运营入口与后台页面。
- Web 角色切换、跨角色主演示清单或 Web 沙箱的 24 小时寿命。
- 真实注册、微信手机号授权、实名、支付、退款、充值、发票或储值。
- 位置、联系人、麦克风或电话权限。
- 多座位、包座、自动分配、改期、换座或店员现场预约。
- 配送、外卖、部分下单、部分领取或部分取消。
- 公开图片、永久分享、真实门店地址或真实硬件品牌型号。

## 4. 目标体验者与使用场景

| 体验者 | 核心诉求 | 设计应提供的证据 |
| --- | --- | --- |
| 首次体验者 | 快速理解产品及演示边界 | 首屏说明、当前任务、明确下一步 |
| 作品集审阅者 | 判断产品是否有真实业务深度 | 价格分段、状态历史、库存冲突、报修联动、持久化 |
| 移动端普通体验者 | 单手完成顾客主流程 | 稳定底部主操作、短表单、清晰返回路径 |
| 辅助技术使用者 | 不依赖颜色完成任务 | 无障碍标签、可读状态文本、足够触控面积与对比度 |

小程序没有真实账号体系。界面中的主演示顾客是固定虚构人物，不应呈现“账号安全”“手机号绑定”或真实社交身份暗示。

## 5. 体验原则

### 5.1 演示边界先于营销表达

首页、模拟支付、报修图片和重置场景都应以简短明确的方式说明边界。提示保持可见但不反复阻塞操作；高风险误解点使用确认面板。

### 5.2 当前任务先于功能大全

首页优先展示当前预约或主演示下一步。门店、会员和历史作为稳定导航存在，但不与当前任务争夺第一视觉层级。

### 5.3 业务状态先于装饰

预约、订单和报修详情统一使用“当前状态 + 下一动作 + 时间/金额影响 + 事件时间线”的结构。状态不能只用颜色或图标表达。

### 5.4 复杂规则逐层展开

预约确认先展示总价、时段、座位和优惠；半小时价格片段可展开查看。异常时直接指出是座位冲突、顾客时段冲突、库存不足或体验券不可用。

### 5.5 本地持久化必须可感知

首次初始化、版本迁移、重启恢复和重置都要有明确状态。不能把本地沙箱包装成云端账号，也不能出现“已同步到云端”等文案。

## 6. 信息架构

### 6.1 一级导航

采用四个底部一级入口：

| 入口 | 页面职责 | 默认落点 |
| --- | --- | --- |
| 首页 | 演示说明、当前任务、当前预约、快捷入口、本地沙箱状态 | `MP-01` 首页 |
| 门店 | 三店浏览、详情、筛选、座位选择与预约 | `MP-03` 门店列表 |
| 行程 | 当前与历史预约，并聚合关联订单、报修和模拟退款 | `MP-16` 行程中心 |
| 会员 | 等级、成长值、体验券及成长记录 | `MP-17` 会员中心 |

“商品”与“报修”不是独立一级入口。商品入口只在已到店或使用中的预约详情出现；报修入口只在当前座位的有效预约详情出现。这样可以把业务资格直接呈现在上下文中。

### 6.2 全局层

所有主页面共享以下信息：

- 顶部或内容首段的“本地演示”标识。
- 可打开的本地演示说明，明确“不与 Web 同步”。
- 失败时可恢复的轻提示区，不以伪成功覆盖真实结果。
- 底部安全区与至少 44px 的有效触控目标。

演示引导以可收起面板或底部抽屉存在，可从首页重新打开，不占用第五个底部导航位。

## 7. 合成故事与设计数据

设计稿必须使用可解释的合成数据，不使用真实品牌、地址或人物资料。

### 7.1 三店工作标签

| 门店工作标签 | 座位 | 营业时间 | 经营特征 |
| --- | ---: | --- | --- |
| 旗舰店 | 96 | 24 小时 | 主演示发生地；预约和商品订单较密集 |
| 标准店 | 64 | 10:00–次日 02:00 | 经营稳定；含交接异常背景 |
| 新店 | 40 | 12:00–24:00 | 利用率较低；含缺货和设备故障背景 |

正式门店名称与城市名在视觉阶段决定；在决定前只使用“旗舰店 / 标准店 / 新店”和“虚构城市”作为工作文案，不写可映射到真实场所的详细地址。

### 7.2 机型与价格数据

| 机型档案 | 体验描述 | 旗舰店基础价 | 标准店基础价 | 新店基础价 |
| --- | --- | ---: | ---: | ---: |
| 标准型 | 1080p / 144Hz | ¥10/小时 | ¥8/小时 | ¥7/小时 |
| 竞技型 | 2K / 180Hz | ¥15/小时 | ¥12/小时 | ¥10/小时 |
| 旗舰型 | 2K / 240Hz | ¥22/小时 | ¥18/小时 | ¥15/小时 |

工作日 06:00–18:00 使用基础价，18:00–24:00 为 `1.20` 倍，00:00–06:00 为 `0.90` 倍；周末营业时段统一为 `1.15` 倍。界面展示整数分计算后的金额，不展示浮点误差。

### 7.3 主演示人物与事件

- 主演示顾客：白银会员，成长值 `860`。
- 初始权益：一张预约固定金额体验券、一张商品固定金额体验券。
- 主预约：旗舰店、竞技型座位、两小时立即预约。
- 报修描述：“耳机右声道无声”。
- 设备故障结果：当前不足半小时片段照常计费，未来完整片段形成模拟退款。

十二种商品和八类备件使用虚构名称；小程序顾客目录只展示门店已上架的可销售商品，不展示维修备件。

## 8. 核心流程

### 8.1 首次启动与恢复

1. 启动时检查本地 schema 与沙箱。
2. 没有本地沙箱时创建当前版本标准种子；存在旧版本时先迁移。
3. 显示简短边界说明：本地演示、不会扣款、不与 Web 同步、不要求真实身份。
4. 进入首页并展开主演示第一步。
5. 再次启动时恢复上次页面所需状态，并从业务记录推导引导进度。

迁移失败时不得进入部分可写状态。页面提供重试与“重建本地演示”两个分级动作，重建前明确说明会清除本机演示数据。

### 8.2 预约主流程

`首页 → 旗舰店 → 立即预约 → 日期/时段/区域/机型 → 座位图 → 预约确认 → 选择预约体验券 → 模拟支付（不扣款） → 预约详情`

关键规则：

- 普通预约开始时间按 30 分钟对齐，时长 1–8 小时，只能预约未来 7 天。
- 立即预约使用当前半小时片段起点，当前片段按完整片段计费。
- 一条预约只包含一个顾客、一个座位和一段连续时间。
- 座位图针对当前所选时段计算可订性；维护中是座位运营状态，已预留/使用中是时段推导结果。
- 创建待确认预约后保留 10 分钟；倒计时归零后变为已过期。
- 价格与体验券结果在创建时形成快照，后台概念上的后续改价不影响它。

### 8.3 本地主故事推进

> **设计前置假设 MP-A01**：规格要求小程序独立完成顾客侧预约、订单与报修体验，但没有定义在缺少员工角色时如何产生“已到店、使用中、制作、维修验证”等门店侧结果。本文档采用可替换的角色外演示工具承接这段缺口。它不改变领域状态机；实现前应在“显式推进工具”与“确定性自动事件”中确认一种机制，并在需要时同步回写规格。

小程序没有员工角色，但必须能独立展示已到店、使用中、订单履约、维修处理和验证结果。设计稿因此预留“推进本地演示”辅助卡片：

- 它属于本地演示工具，不属于顾客业务权限。
- 文案必须明确“仅推进本机合成故事”，不能写成顾客办理到店、开始维修或确认领用备件。
- 工具只触发预置的合法结果，并在结果后回到顾客可见页面。
- 正常业务区不展示店员、店长或总部操作按钮。

实现若改用自动种子事件或其他等价机制，可替换该卡片，但必须继续满足“小程序独立走完顾客侧故事”和“不伪装员工权限”两个条件。

### 8.4 商品订单流程

`已到店/使用中预约详情 → 商品目录 → 购物车 → 确认订单 → 选择商品体验券 → 模拟支付（不扣款） → 订单详情`

- 没有同店已到店或使用中预约时，不展示可执行下单入口。
- 创建订单时整单检查并预留库存；任一行不足则整单失败，保留购物车供修改。
- 待模拟支付保留 10 分钟，超时后释放库存与占用的体验券。
- 顾客仅能在制作开始前取消；制作中和待取阶段只展示进度与柜台取货提示。
- 关联预约因设备故障结束后，已经完成模拟支付的订单仍继续柜台履约。

### 8.5 报修流程

`使用中预约详情 → 报修 → 问题描述 → 可选本地图片/样例图 → 提交 → 报修详情 → 公开处理动态 → 模拟退款结果`

- 报修必须关联当前座位及其机型。
- 同一座位已有未关闭报修时，直接展示已有报修单，不创建重复记录。
- 最多三张 JPEG、PNG 或 WebP 图片，每张不超过 5 MB。
- 拒绝相册/相机权限或图片处理失败时，仍可通过文字或内置样例图提交。
- 图片只保存在当前设备的本地沙箱；界面不得声称已上传或已与 Web 同步。
- 顾客只看到公开状态、公开处理说明和验证结果。

### 8.6 重置流程

`首页演示设置 → 重置本地演示 → 二次确认 → 创建当前版本标准种子 → 首页`

确认内容必须列明：预约、订单、报修、会员成长和引导进度都会恢复到标准故事；此操作只影响当前设备，不影响 Web 或其他体验者。

| MP-16 | P0 | 行程中心 | 当前/未来/历史分组，关联订单、报修、模拟退款 | 空状态、筛选、跨经营日、记录已归档 |
| MP-17 | P0 | 会员中心 | 等级、成长值、升级进度、体验券、成长记录 | 青铜/白银/黄金、可用/占用/已使用/过期券 |
| MP-18 | P0 | 本地演示设置 | 本地存储说明、schema/种子版本、重置 | 正常、迁移提示、重置确认、重置成功/失败 |
| MP-19 | P2 | 通用系统状态 | 安全错误信息、恢复动作 | 存储不可用、非法状态、重复操作、未知错误 |

## 10. 关键页面内容层级

### 10.1 首页 `MP-01`

从上到下的默认层级：

1. “本地演示”状态条，包含“不与 Web 同步”的短说明入口。
2. 当前故事卡：当前步骤、为什么要做、唯一主动作。
3. 当前预约卡：门店、座位、时段、状态、倒计时或下一时间点。
4. 快捷入口：继续预约、查看行程、会员权益。
5. 三店简览或运营故事摘要，避免模拟真实广告促销。
6. 演示设置与重置入口。

当存在待确认预约时，“继续模拟支付”优先于新建预约；存在使用中预约时，“商品”和“报修”成为主要动作。

### 10.2 座位图 `MP-06`

- 顶部固定展示当前选择的日期、时段和机型，可返回修改。
- 图例同时使用形状/纹理或文字缩写与颜色，明确“维护中”与“该时段不可订”的差异。
- 座位选中后显示底部摘要：编号、区域、机型、半小时起价/预计总价和继续动作。
- 96 座旗舰店需要分区浏览、缩放或局部导航；不能通过极小点击目标一次性平铺全部座位。
- 改变时段或筛选后重新计算可订性；已选座位失效时清除选择并说明原因。

### 10.3 预约确认 `MP-07`

首屏必须能看到：门店、座位、开始/结束时间、时长、模拟总价、体验券结果和“不扣款”说明。价格片段展开后展示每个半小时的时段、规则与金额；不以单一“均价”替代价格快照。

体验券卡说明适用门店、业务类型、时段、最低金额、有效期和本次减免。不可用券保留可解释原因，不只置灰。

### 10.4 预约详情 `MP-09`

详情页固定结构：

1. 状态与关键时间。
2. 唯一主要动作或明确的等待说明。
3. 门店、区域、座位与机型。
4. 模拟金额、体验券、价格片段和模拟退款。
5. 关联商品订单与报修。
6. 不可编辑的业务事件时间线。

终态页面不再展示可执行主按钮，只提供再次预约、查看历史或回到首页。

### 10.5 订单详情 `MP-12`

- 使用进度组件展示“待模拟支付 → 已模拟支付 → 制作中 → 待取 → 已完成”。
- 已过期和已取消是分支终态，不应错误显示在成功进度线上。
- 柜台取货信息持续显示门店与关联座位。
- 制作开始后取消造成的库存损耗属于员工侧结果；顾客只需看到取消、全额模拟退款和体验券不恢复，不展示库存成本。

### 10.6 报修详情 `MP-15`

顶部显示公开状态与当前说明；中部展示座位、机型、顾客描述和本地图片；底部按时间显示公开处理动态、设备中断影响与验证结果。不得显示处理人内部备注、备件成本或完整审计信息。

### 10.7 会员中心 `MP-17`

- 等级名称固定为青铜、白银、黄金。
- 主指标名称使用“成长值”，不使用“积分”“余额”或“返现”。
- 显示当前累计值、下一等级门槛与终身不降级说明。
- 体验券按可用、占用、已使用、已过期分组；占用券展示关联交易与释放条件。

## 11. 业务状态与顾客动作

### 11.1 预约

| 状态 | 顾客看到的核心信息 | 顾客动作 |
| --- | --- | --- |
| 待确认 | 10 分钟倒计时、价格快照、占用的体验券 | 模拟支付（不扣款）、取消 |
| 已确认 | 到店窗口、计划开始时间、座位 | 开始前取消；等待门店处理 |
| 已到店 | 最早开始时间、座位、柜台商品入口 | 下单；等待开始使用 |
| 使用中 | 计划结束时间、当前座位、关联订单 | 下单、报修 |
| 已完成 | 最终模拟金额、成长值、可能的模拟退款 | 查看历史、再次预约 |
| 已取消 | 取消原因、体验券与模拟退款结果 | 查看历史、再次预约 |
| 已过期 | 待确认超时或未到店原因、释放结果 | 再次预约 |

### 11.2 商品订单

| 状态 | 顾客看到的核心信息 | 顾客动作 |
| --- | --- | --- |
| 待模拟支付 | 10 分钟倒计时、整单预留、总额与券 | 模拟支付（不扣款）、取消 |
| 已模拟支付 | 等待制作、柜台取货、关联预约 | 制作开始前取消 |
| 制作中 | 正在制作、预计下一状态 | 查看进度 |
| 待取 | 柜台与门店、全部商品 | 前往柜台、查看进度 |
| 已完成 | 领取完成、最终模拟金额、成长值 | 查看历史 |
| 已取消 | 取消原因、模拟退款、体验券结果 | 查看历史 |
| 已过期 | 未完成模拟支付、库存与券已释放 | 返回商品目录 |

### 11.3 报修

| 状态 | 顾客可见内容 | 顾客动作 |
| --- | --- | --- |
| 新建 | 已提交、等待门店分派 | 查看动态 |
| 已分派 | 已安排处理、公开处理说明 | 查看动态 |
| 处理中 | 座位维护、预约影响、公开处理说明 | 查看动态与模拟退款 |
| 待验证 | 已提交解决说明、等待验证 | 查看公开说明 |
| 已关闭 | 验证成功、座位恢复、最终结果 | 查看历史；新故障新建报修 |

## 12. 异常与恢复状态

| 场景 | 页面反馈 | 恢复动作 |
| --- | --- | --- |
| 座位时段冲突 | 明确指出座位已不可订，保留其他条件 | 返回座位图重新选择 |
| 顾客跨店时段冲突 | 展示冲突预约的门店与时段 | 查看原预约或调整时间 |
| 待确认超时 | 状态变为已过期，不显示模拟支付成功 | 重新创建预约 |
| 整单库存不足 | 指出不足商品，订单不创建 | 修改数量或移除商品 |
| 订单支付前预约终止 | 订单已取消、库存与券已释放 | 查看关联预约 |
| 重复报修 | 不创建新单，展示已有未关闭报修 | 打开已有报修详情 |
| 图片权限拒绝 | 解释图片为可选 | 继续文字提交或使用样例图 |
| 本地存储写入失败 | 不显示业务成功；保留当前输入 | 重试或返回，必要时重建沙箱 |
| schema 迁移失败 | 阻止进入部分状态 | 重试迁移或确认重建 |
| 重复点击/处理中 | 主动作进入稳定处理中状态 | 等待同一结果，不重复创建 |

所有错误使用安全、可行动的中文文案；不显示堆栈、内部路径或技术对象名。

## 13. 组件与交互清单

设计系统至少需要覆盖：

- 本地演示状态条与边界说明面板。
- 页面标题、底部导航、底部固定主操作与安全区。
- 主演示步骤卡、进度面板和“推进本地演示”辅助卡。
- 门店卡、营业时间、机型标签和价格概览。
- 日期/时段选择器、时长步进、筛选标签和座位图。
- 状态标签、倒计时、业务事件时间线和关联对象卡。
- 半小时价格明细、金额汇总、体验券卡和不可用原因。
- 商品卡、数量步进、购物车浮层、订单履约进度。
- 图片选择、预览、删除、失败回退和样例图选择。
- 空状态、加载/处理中、内联错误、冲突面板、确认对话框和结果页。

确认类动作中，“取消预约”“取消订单”“重置本地演示”采用明确对象与影响说明，按钮文案不能只写“确认”。

## 14. 内容与文案规范

- 所有支付相关动作完整写为“模拟支付（不扣款）”或同等明确文本。
- 所有退款相关结果写为“模拟退款”，不写“原路退回”或真实到账时间。
- 使用“顾客”“座位”“机型档案”“成长值”“体验券”“报修单”等领域正式词。
- 座位页面区分“座位运营状态”和“所选时段可订性”。
- 商品页不显示备件；报修页不把备件称为商品。
- 时间默认使用上海时间；跨午夜同时显示完整日期，经营日只在历史统计语境中出现。
- 金额使用人民币符号和两位小数；计算依据为整数分。
- 自由文本附近显示长度和隐私提示；报修描述最多 500 字。

## 15. 响应式、无障碍与微信约束

- 高保真主稿至少覆盖一种常见 iOS 微信视口与一种常见 Android 微信视口，并验证窄屏、长文字和底部安全区。
- 所有交互目标至少 44px，关键主操作不被系统手势区遮挡。
- 状态、座位可订性、错误和图表信息不得仅靠颜色表达。
- 交互控件提供可理解的无障碍标签；座位标签应包含编号、机型和可订结果。
- 支持系统字体放大后的主要流程，不用固定高度裁切金额、状态或错误文本。
- 图片选择前说明用途与本地保存边界；拒绝权限不造成流程死路。
- 首屏与分包结构要支持小程序主包控制在平台探针确认上限的 80% 内，非首屏页面可进入分包；视觉稿不依赖一次加载大量高清资产。

## 16. 顾客 H5 复用边界

顾客 H5 不形成第三套独立产品设计。它复用本文档的顾客信息架构、页面职责、状态组件与主要文案，并在 Web 设计系统中做以下替换：

- “本地演示”替换为“演示数据 / Web 沙箱”，数据由服务端权威保存 24 小时。
- 增加 Web 角色切换、沙箱业务时钟、跨角色主演示清单与重置入口。
- 去掉本地 schema 迁移和本地存储设置。
- 报修图片使用 Web 私有上传与净化流程，不使用“小程序本机保存”文案。
- Web H5 从 360px 起完整可用，并遵守[管理系统文档](../management-system/prod.md)中的共享演示壳规则。

小程序和 H5 使用相同合成故事与领域规则，但实例标识、当前状态和持久化完全独立；设计稿不得表现为两端同步。

## 17. 设计交付物与验收

正式设计稿至少交付：

1. `MP-00` 至 `MP-18` 的页面或明确组件复用说明，所有 `P0` 页面不得缺失。
2. 可点击的预约、商品订单、报修和重置四条主流程原型。
3. 预约、订单、报修三套完整状态组件及终态分支。
4. 座位图的可订、已预留、使用中、维护中和已选五种可辨识状态。
5. 正常、空、加载/处理中、冲突、超时、权限拒绝、本地存储失败和迁移失败状态。
6. 组件清单及关键交互规格：尺寸、间距、触控区域、禁用、错误、长文本和安全区。
7. 视觉稿内的真实合成数据与正式中文文案，不使用 `Lorem ipsum`、无意义占位数字或真实品牌。
8. 一份小程序与顾客 H5 的复用/差异标注，避免后续实现误判为状态同步。

验收完成条件：体验者只看原型即可从首次启动走到预约完成、商品订单、报修公开结果和本地重置；任一时刻都能识别演示边界、当前状态和唯一主要动作。

## 18. 视觉阶段待定项

以下内容应在视觉探索阶段决定，不在本文档中预设答案：

- 品牌标志、色彩、字体、图形语言与动效强度。
- 三家门店正式名称、虚构城市名、区域名称。
- 十二种商品、八类备件和背景人物的正式虚构命名。
- 门店图片、插画与机型示意资产方向。

视觉方向应兼具电竞场景辨识度与业务状态清晰度，避免使用真实赛事、游戏、硬件品牌资产，也避免把演示产品包装成可真实预约或真实支付的门店服务。
